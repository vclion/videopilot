# 视频问答：Qwen 直接回答

视频问答由 Qwen 直接读取候选 MP4 片段、字幕和当前话题上下文并生成答案；追问改写和画面索引也使用 Qwen。下载、AI 总结、会员、话题隔离及历史记录继续使用现有流程，AI 总结仍调用 DeepSeek。此链路只作用于 `mode: question`。

## 启用

在本地 `.env` 填写服务提供方的配置并重启：

```dotenv
VIDEO_ANALYSIS_ENABLED=true
QWEN_VL_API_KEY=你的密钥
QWEN_VL_BASE_URL=服务提供方的HTTPS基础地址
QWEN_VL_MODEL=服务提供方的模型名称
```

基础地址不包含 `/chat/completions`。适配器需要服务支持 OpenAI 兼容的 `video_url`、MP4 Base64、单次请求多个视频、`fps: 2`、`enable_thinking: false` 和 JSON 输出。2026-10-02 已使用本地配置的 `qwen3.8-omni-flash` 验证真实 MP4、多片段输入、追问与模型选择片段；具体画面识别结果仍依赖视频清晰度。问答无需配置 DeepSeek 密钥；AI 总结仍需要其配置。

```bash
.venv/bin/python run.py
```

默认 `VIDEO_ANALYSIS_ENABLED=true`。Qwen 配置不完整时，问答接口直接提示缺少配置，不创建任务。显式设置 `false` 可恢复旧的 DeepSeek 字幕问答。

## 问答流程

1. 获取字幕、读取当前话题记忆；有历史上下文时由 Qwen 改写追问，改写失败则保留原问题。
2. 下载并缓存同一链接的视频；B 站字幕遵循 URL 的 `p` 参数，短链接先解析到实际地址。
3. 建立 0–10、10–20 秒等固定窗口。字幕跨边界时关联到所有相交窗口；没有字幕的窗口保留。
4. Qwen 分析所有窗口，记录物体属性、动作、位置关系和可辨认画面文字。每个成功片段立即保存到 SQLite，中断后后续提问续建。
5. Qwen 阅读全部窗口的字幕、画面记录和不确定性，根据问题含义选择相关片段，不做关键词匹配。索引较长时分批阅读，再比较各批候选；选择后补相邻窗口。口语表达和记录不必使用相同字词，例如“手里拿的什么枪”可以选中“玩家手持带瞄准镜的步枪”。片段选择失败会明确报错，不伪装成没有相关画面。
6. 一次最终 Qwen 请求直接携带选中的 MP4 文件、对应原视频时间范围、字幕证据、问题和当前话题上下文。
7. Qwen 返回答案、要点、引用、追问建议和话题记忆。保留现有回答字段，附加 `video_analysis` 状态及证据时间范围；程序过滤未知来源和超出真实片段的时间引用。

首个问题会等待索引工作，前端显示已处理片段数量。整段 10 分钟视频约有 60 个索引窗口，因此首次处理会产生多次视频模型调用；之后复用全片索引，每次问答先由 Qwen 选择片段，再把候选视频发送给 Qwen。选择片段会增加文本模型请求，长索引可能需要多次请求。画面索引只帮助选择，最终回答直接读取视频。最终答案不缓存，避免复用不符合当前上下文的答案。不同话题的聊天记忆仍然隔离；视频素材和客观画面索引可复用。

索引与问答所见视频统一使用原视频时间。最后一个片段不足 2 秒时补重复尾帧满足视频接口最短长度，引用范围仍限制在真实片段内。时间校验容许保留三位小数带来的最多 0.5 毫秒舍入误差，并将结果限制回真实范围，不接受补时帧的引用。索引失败会显示具体片段、时间范围和错误原因。视频抽样为 2 FPS，不代表逐帧覆盖。

## 缓存与资源限制

```dotenv
VIDEO_INDEX_MAX_CHUNKS_PER_RUN=180
VIDEO_RETRIEVAL_TOP_K=3
VIDEO_MAX_CLIPS_PER_QUESTION=6
VIDEO_MAX_MINUTES=30
VIDEO_SOURCE_MAX_MB=300
VIDEO_CACHE_MAX_MB=1024
VIDEO_CACHE_TTL_HOURS=168
```

- 每次索引最多处理 180 个新片段；达到上限时保留覆盖范围，下次提问继续。
- `VIDEO_RETRIEVAL_TOP_K` 保留原配置名称，控制 Qwen 最多选择 3 个核心块；连同邻居最多向最终回答发送 6 块。
- 单个切片原始文件最多 7 MB，一次最终请求的切片合计最多 15 MB；超过限制时明确报错。Base64 会增加请求体大小，实际平台限制仍需验证。
- 原视频和切片保存在 `data/video_cache/`，分析保存在 `data/db/video_cache.db`，均被 Git 忽略。
- 素材按规范化链接（保留分 P）和视频内容哈希区分，画面索引另按模型接口、名称及分析版本区分；切换模型会重新生成索引。旧的问题观察缓存不参与当前问答。
- 清理优先淘汰闲置超过期限或最久未使用的素材。素材从准备到最终 Qwen 请求完成均受保护；并发请求下容量可能短暂超过目标，空闲后再清理。
- 本实现按单个服务进程设计，同一视频的并发请求由进程内锁串行处理。需要多进程部署时，应补跨进程任务锁与独立索引队列。

## 字幕与错误处理

平台字幕现在保留时间戳。旧缓存只有正文时，视频增强会尝试重新提取字幕；失败后保留原有文本证据并标记无法按时间对齐，不猜测时间。字幕明显超出视频时长时也不强行对齐。没有可用字幕的视频可以依靠视觉索引回答，但声音信息不在这条视觉链路内。

视频获取或索引失败时，保留已有字幕与已完成索引，并明确显示失败/部分覆盖状态。仍有候选片段时 Qwen 读取这些片段；没有片段时由 Qwen 仅依据字幕回答并说明未获得视频证据。检索零命中不随机挑片段，也不声称全片不存在相关内容。索引阶段一次服务失败后停止继续请求未缓存片段，避免连续超时。最终 Qwen 调用失败时任务失败，不自动切换到 DeepSeek。

Qwen 输入中单独标注字幕、视频及历史上下文，按证据对象裁剪文字预算，保留所有实际发送的视频标签。前端显示的证据范围与实际模型输入保持一致；不把未经引用支持的历史记忆当作画面事实。

“一共几次、第一次、最后一次”等问题会标记 `global_limited`。采样索引与局部回看不足以证明精确全片计数，当前提示回答模型说明限制。全局事件扫描及向量检索属于后续阶段。

## 自行验证

先配置 API 并用短视频验证，再逐步增加长度。至少检查：

1. 字幕可回答的问题，原有回答与话题记忆是否正常。
2. 字幕没有提及的颜色、物体位置或屏幕文字，是否能检索到对应时间范围。
3. 同一视频再次提问，索引是否直接复用，最终请求是否仍携带候选 MP4。
4. 视频获取失败时是否提示无视频证据；Qwen 服务失败时是否明确显示任务失败。
5. 索引处理上限较小（例如 2）时，覆盖范围是否明确，后续提问是否续建。

接口仍为 `POST /api/agent/runs` 和 `GET /api/agent/runs/{run_id}`。新增元数据状态包括 `ready`、`partial`、`unavailable`、`no_match`、`global_limited`。

本地回归测试使用模拟模型响应和实际 FFmpeg 切片，不调用外部模型：

```bash
.venv/bin/python -m unittest discover -s tests -v
```
